Why PM1 differs from the accepted counter

program.rs:181 recognizes the shared clock before sampling.rs:103 classifies independent
cells. PM1 has one recognized clock, three clock-owned cells and two owned observers;
no independent memory events are required. The error occurs after logical extraction,
at program.rs:404 -> clocked.rs:26. logic.rs:321 collects response_sources from ALL
piston responses, before output extraction; it is not the clock-root's dependency set.
The counted sources are all minecraft:lever:
  control (0,2,0) -> world (40,32,40)
  I3 (6,5,2) -> (46,35,42)
  I2 (6,5,4) -> (46,35,44)
  I1 (6,5,6) -> (46,35,46)
Extracted roots show the clock depends only on control at threshold 0; each cell's data
root depends only on its own data lever at threshold 0. No stored-state-dependent
control or power cycle exists in those roots. There is one writer, observer (4,3,0),
on the lower bus; the upper data dust powers via QC without delivering writes.

COUNTER_BASIC compiles in all eight comparisons. Its clock is local (2,11,19), world
(42,41,59), with 16 memory cells. Its region's sole ordinary response source is a
redstone_wall_torch at (7,8,2), world (47,38,42), facing south. Stored geometry supplies
its counter data, so it adds no external data lever sources to response_sources. Its
clock root traverses an Actuator edge (132), which the existing validator already walks.
That is why similar BUD update delivery passes there but PM1 fails. Restricting source
collection to the clock root alone would still leave PM1's lever outside the torch whitelist.

Native sampling and ordering evidence

Each original is first run without perturbation for 12 ticks. Next, individual data
levers are toggled with 8 idle ticks each; NO memory samples occur and stored state holds.
Then Trigger/enable runs 24 ticks, stops 12, data is toggled back while stopped, and it
runs/stops again. Repeated triggers with unchanged data retain repeated native callbacks
and same-value checks, without extra stored-state changes. Both committed memory poses
are reached through the interpreter. All heads were probed in separately prepared
extended/retracted poses using the LIVE head block; present heads forward to their base,
near redstone payloads do not. Native data-without-notification and head eligibility
have asserts in the new capture. These probes are labelled controlled preparations.

Let T be the tick before a trigger action; no tick is silently advanced between actions.
PM1 and mixed release: generator Retract commits T+1. Sampling/reset observers turn on
T+3 in scheduled FIFO order. Dust callbacks sample the memory bases, and their piston
events execute in that same event phase. The restored generator base queues its Extend
for T+4. Observers turn off T+5. With extending memory, outputs first turn on T+7.
Next generator retract is T+7; subsequent observer deliveries repeat every six ticks.
Both observer pulse edges remain delivered native checks, including unchanged data.
Stop/restored power can cancel a queued generator retract at event execution.

ANPU stable data: trigger changes queue generators immediately; generator events at T+1
write their base/head geometry and synchronously notify the appropriate memory BASE.
Memory events enqueued from those callbacks run in the same FIFO event phase. Extension
movement restores payloads at T+3; repeaters turn ON T+5. Retraction output turns OFF T+3.
I1 additionally receives the updater's head-completion callback. I2 receives updater
base callbacks, including restoration on retraction, but no head-completion delivery
on extension. “Generator pose changed” misses those different callback sequences.

Instant stable data: Trigger OFF queues generator retracts; T+1 commits them, removes
their adjacent heads, and notifies memory bases. Torches turn ON T+2 as ordinary scheduled
events; restored generator bases queue Extend for T+4. Memory retraction output turns
OFF T+3; extension output turns ON T+5. Trigger ON suppresses torches later while QC
keeps generators extended; it does not itself produce another committed generator edge.
“Instant” here means the memory recheck is delivered in the generator event phase without
a separate observer sampling delay. It does not erase scheduled torch/repeater work,
movement completion, FIFO order or the opportunity to cancel a queued event.

Native engine order: plot/mod.rs:prepare_operation and advance_operation drain ordinary
scheduled ticks by priority/FIFO, then piston events including newly enqueued ones, then
an identity-checked snapshot of moving entities. Movement completion callbacks can enqueue
piston events for the following tick's event phase. piston.rs:106 rechecks live power
before executing a requested action. piston.rs:172/216 notify writes; :292 restores and
notifies completed movement; :358 delivers neighbors. redstone/mod.rs:292 forwards live
piston-head callbacks. Power checks use piston.rs:40 and do not themselves write memory.

Identical native/compiled comparisons

The successful ANPU/instant cases were replayed with the SAME initial snapshot, lever
actions and idle counts under all four flags and both budgets. All eight compiled
projections agree with each other; --assume-instant does not choose a different executor.
The stable-data episode matches every settled endpoint in both variants of both files.
It still differs in FOUR observed repeater-output frames per file: compiled output work
can be scheduled from an immediate logical memory write while native must execute piston
events and finish movement first. Raw frames also expose the physical moving poses.

Three controlled schedules start from each original saved snapshot, after 12 idle ticks:
1. Trigger edge, reverse Trigger before ANY tick, then 12 ticks.
   Native cancels queued updater work. In instant, native outputs remain I1=ON,I2=OFF;
   compiled outputs become ON/ON. I2 was sampled from a request whose native movement
   never executed. ANPU outputs happen to agree (OFF/OFF) because data is already OFF,
   but compiled diagnostics record four bank commits from the two cancelled pose edges.
2. Trigger edge, flip every data lever before ANY tick, then 18 ticks.
   ANPU native memories/outputs end ON/ON; compiled OFF/OFF. Native samples updated data
   at generator event execution; compiled samples stale data during on_use_block.
   Instant final endpoints reconverge after later torch/generator work, but intermediate
   output frames differ. Reconvergence is not cancellation/order equivalence.
3. Trigger edge, run exactly ONE tick, flip every data lever, then 18 ticks.
   ANPU native outputs end I1=ON,I2=OFF; compiled OFF/OFF. At T+3 moving-head completion
   rechecks I1 using new data; its queued Extend executes T+4 and output turns ON T+8.
   I2 has no corresponding extension-head delivery. Instant final outputs agree OFF/OFF
   but five intermediate repeater-output frames differ.

These differences are compiler execution defects in local comparisons, not differing
schematic initialization: imported poses and schedules are identical on both sides.
PM1/mixed compiled comparison attempts remain rejected; their native traces are captured
but no compiled equivalence claim is made. No admission check was suppressed for a run.

Callers and smallest implementation recommendation

Traced path: Compiler::compile (redpiler/mod.rs:312) -> analysis::analyze ->
families::recognize / ports::discover -> instant::regions::split -> program::prepare_region
-> clocked::recognize -> sampling::recognize -> geometry/ownership/attachment/boundary
checks -> observer::certify -> pending-work checks -> logic::extract_ideal_with_state
-> sampling::validate / ClockedProgram::validate -> graph passes -> DirectBackend bind.
Runtime: direct/mod.rs set_node/on_use_block/tick_after_callbacks -> evaluate_instant ->
instant::Runtime::advance; outputs return through existing ordinary propagation/scheduler.
Reset, flush and memory geometry callers were also read. Clock/sample recognition and
validation have one production preparation caller; the remaining callers are diagnostics
and tests. There is no alternate interpreter fallback executor to extend.

PM1 judgment: the bank/control is already logically representable but misclassified by
the region-wide source validator. Smallest admission correction is to traverse the
CLOCK ROOT's Signal leaves, following Actuator response edges with the existing dependency
walker pattern, instead of checking all response_sources. Admit an ordinary supported
binary control with proved release polarity, including this lever, while retaining the
stored-data/unsupported-state rejection. Collecting clock leaves alone is insufficient
while the torch-only condition remains. Preserve all construction and structural guards.
Before shipping, prove the existing clock schedule against first delivery, pulse-off
delivery, stop/cancel and restart: Runtime::advance (:543) currently samples immediately
on activation and thereafter every six ticks (:565), while native first delivery is T+3.
Therefore this investigation does NOT establish that a validator-only edit satisfies the
requested exact ordering contract. No “compile succeeds” patch is recommended as complete.

ANPU judgments, both variants: independent sampling topology is already recognized;
strict native ordering needs a specific execution extension, not weaker construction
proofs. sampling.rs:222 aggregates adjacent generator base/head into one pose-edge source.
instant.rs:572 commits a delivery when the evaluated generator response changes. This
occurs on input propagation before native requests can be cancelled or execute. It also
omits movement-completion callbacks. Extend the existing logical runtime/scheduling
machinery with certified delivery phases for empty generators: request, live-power
validation at event execution, ordered base/head writes, and head/base completion
notifications. Preserve same-value deliveries and eligibility at the callback phase.

Instant judgments: already accepted with complete context and correct stable endpoints;
needs the same cancellation/ordered-delivery extension for the requested semantics.
Keep ordinary torch and repeater nodes on their existing scheduler. Do not force stored
I2 to its current power state or treat an evaluated generator response as completed motion.

Mixed judgment: specialization misclassification is established, but generic execution
equivalence remains unproved. General sampling preparation must not be pre-empted merely
because one downward clock-shaped actor occurs in a conservatively merged region. Select
the shared-clock specialization only for a bank whose writer ownership it actually proves,
or retain separately certified per-writer domains in the existing logical program. Do
not catch arbitrary clocked errors and blindly retry generic admission. The generic
diagnostic's ordinary observer feedback still needs ownership, pending-work, callback,
start/stop/cancel and scheduler proof before executing it. Removing the independent-writer
guard or replacing a two-branch notification model with one timer is not a valid fix.

No change is needed to support selection escape: use a selection with required loaded
context, and keep the boundary checks. All fixes must retain geometry, exact payload
ownership/material, block entities, attachment checks, pending events/motions/ticks,
construction proofs, acyclic response checks and transactional failed compilation.
Default and --assume-instant must share delivery semantics; only proofs may differ.
