# Experimental RedGear session service (protocol 3)

This is an experimental external adapter for the native MROWW headless session API. It is not the Minecraft network protocol or RedGear's old protocol-2 process launcher. Build and run it from this repository:

```sh
cargo run -p mroww-redgear-api -- 127.0.0.1:8765
```

Builds may set `MROWW_API_REVISION` to the exact clean source commit at build time. Without it the handshake reports `unversioned`; clients requiring a verified revision must reject that build. An environment value is only a label, not proof that the checkout was clean or that the commit was published.

The operator starts and owns the service separately from Paper. It accepts IPv4 loopback only; it has no authentication or encryption and must not be exposed to a network. Each TCP connection owns at most one session. `close`, disconnect, idle read timeout or failed response delivery drops that session; RedGear must never terminate the shared service. At most four connections are accepted at a time. Logs go to stderr. A caller must use connection and response deadlines and must treat timeout or disconnect as a fatal ambiguous outcome, without retrying input or a drain.

Messages are UTF-8 JSON objects terminated by newline, one request in flight per connection. The byte limit, including newline, is 1,048,576. Requests contain an unsigned integer `id` and string `op`; responses echo `id` and contain `ok`. Malformed JSON, overlong lines, read/write timeout or a broken connection closes the connection and drops its session. Errors contain `error` and `fatal`; fatal errors close the connection after the response. Invalid inputs rejected before execution do not mutate the session. If execution fails after starting an input or tick batch, it is fatal; the host must restore its world.

The first request is `{"id":1,"op":"rawr","protocol":3}`. The reply identifies the engine, protocol, registry, Minecraft data version, supported modes, block/entity/tick/effect capabilities, boundary and limits. Reject version or capability mismatches before any Paper world mutation. Current admission is intentionally narrow: only air, stone and lever states; no pending ticks, block entities or ordered effects; closed boundary; Minecraft data version 4325. A real circuit requiring other blocks or effects must not be activated. The current Paper 26.3 build is not proven compatible with that registry. Limits are 64 blocks per axis, 65,536 cells, 64 inputs and 64 ticks per call. These are not fidelity or performance claims.

`load` uses `size:[x,y,z]`, `data_version:4325`, `boundary:"closed"`, a complete `palette` of canonical block-state strings, sparse `blocks:[[x,y,z,palette_index],...]`, and empty `entities` and `ticks` arrays. Coordinates are selection-local; omitted cells are air. It validates the entire input and constructs a fresh native session before publication. `compile` takes `mode:"interpreter"` or `"compiled"`; a compile failure does not change the loaded world. Once compiled, use `advance` with `ticks`, an ordered `inputs` array of `{kind:"use",pos:[x,y,z]}` and `projection` boolean. Inputs are applied before ticks. `projection:false` retains changes for a later drain; `projection:true` consumes the same change stream as `project`.

`inspect` takes `pos` and returns `state` and `tick`. `project` takes `kind:"baseline"` or `"changes"`; both return `states`, `changes:[[x,y,z,index],...]`, and `tick`. Delta records include air. Changes coalesce to the most recent state per position. An empty drain is empty. A baseline reads current non-air state without consuming the delta stream. If a response exceeds the message limit the connection closes and the session is dropped; the host must not retry an ambiguous drain. `close` releases the session and closes the connection.

The service closes a connection when a request exceeds 30 seconds and has socket read and write timeouts. It cannot yet cancel native compilation or a tick already executing: the session and one of the four connection slots remain occupied until that operation returns. A peer disconnect during an operation is also observed when it returns and the response is written. Registry mapping, full block/tick/effect support, Paper integration, recovery, and stronger resource isolation require further work before production use.
