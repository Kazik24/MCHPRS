# Side B review: basic preparation passes

Date: 2026-10-12. B1 source research complete; B2 remains a proposed slice for human review. No runtime rewrite or Step 05 source change is included.

## Decision and evidence boundary

Start with local literal guard simplification, retaining explicit old-to-new guard IDs. Consider exact guard interning only after measuring duplicate records. Skip profile interning initially: geometry, electrical preparation, and callback preparation already intern profiles by raw block state within their respective construction stages. A second profile table rewrite needs measured residual duplication, not an assumption that there is one profile per site.

The current rich electrical plan is not an executable graph. This review establishes preparation legality, not interpreter parity, execution admission, or speedup. Step 05 is still awaiting review. B2 must use the reviewed assembly boundary when it exists; it must not invent a conversion that discards site-based electrical plans to get an optimizer running.

## Source inventory and reuse

Paths below describe the current working tree, including ongoing Step 05 changes; those files were only read. The legacy pipeline lives in [passes/mod.rs](../../../../crates/core/src/redpiler/passes/mod.rs). It always identifies nodes, searches inputs, and clamps weights. Optimization then runs deduplication, constant folding, comparator-output pruning, constant coalescing, logic coalescing, and optional IO-only orphan pruning. Export is separately enabled. Optimization is suppressed when `allow_native` selects native propagation for comparators or cycles; this existing behavior is not authorization for a rich-graph fallback.

## Rich representation and affected references

[program_graph.rs](../../../../crates/core/src/redpiler/program_graph.rs) separates construction from the legacy graph. `CircuitDraft::lower` validates first and stably groups links by destination; routes retain their own delivery sequence. Validation checks ID bounds, guard cycles, node/state ownership, resource contacts and initial conflicts, route receivers, sequence numbers, and callback-edge correspondence. It is structural validation, not proof of an executable admitted circuit or of all reachable contact states.

[analysis/electrical.rs](../../../../crates/core/src/redpiler/analysis/electrical.rs) retains source sites, literal faces, stored wire reads, conductor policies, normal/side/QC ports, guarded wire relations, and comparator override plans. `push_guard` appends without deduplication. `join_guards` already maps empty All to Always and singleton All to its child; `any_guards` handles empty/singleton Any. `all_guard` can still append `All([Always, g])`, and repeated contact predicates are constructed independently. This is a source witness for potential guard simplification, not a measured duplicate count.

[analysis/geometry.rs](../../../../crates/core/src/redpiler/analysis/geometry.rs) interns profiles by raw state in `build_draft`. Electrical preparation upgrades their electrical classification and extends the same table by raw state. [analysis/callbacks.rs](../../../../crates/core/src/redpiler/analysis/callbacks.rs) extends it with `profile_for`, and already removes its known Always operand in `combine_guards`. Reuse these conventions; complete profile equality must still compare raw state, registry type, solid, transparent, cube, and electrical classification.

A future remap must reach all of these places, including plans outside `CircuitDraft`:

- Guard references: Not/All/Any children; contact variant `when`; every LinkKind guard; route delivery guards; `ElectricalLink.guard`; `WireRelation.guard`; comparator `far_override` guard.
- Profile references: contact variant profile; resource material; constant SiteSource; `SiteTest::Profile`; any exported or captured `ObservedSite.profile` associated with the transformed program.
- Provenance: return maps for every original record, including multiple original IDs mapping to one record. Keep site positions, node identities, route IDs, delivery sequence/view/direction/receiver, and callback `(route, sequence)` unchanged.

Run before runtime state/captured frames exist. Do not leave geometry or an export retaining references into an old profile table while presenting it as the new table. Callers and assembly must define which table each view owns. No configuration, binary format, scheduler, or ordinary-backend change is needed for this slice.

## Literal guard legality

Use T = Always and F = Not(T); there is no False variant. Normalize children in acyclic dependency order, without assuming table order (validation permits forward references). Retain operand order and views.

| Operation | Permitted first rule | Preconditions / witness |
| --- | --- | --- |
| Not | Not(T) -> F; Not(F) -> T | The operand is a proven literal, not a saved-state test. |
| All | Drop T; empty -> T; singleton -> child | Preserve remaining order. |
| Any | Drop F; empty -> F; singleton -> child | Preserve remaining order. |
| All containing F / Any containing T | Collapse only an entirely literal expression in the first slice | Mixed expressions may contain captured-site requirements or receiver-validation witnesses. Do not erase those predicates until their evaluation and structural-validation contract is reviewed. |
| State/Site leaf | Preserve exactly | `ResourceEnabled`, `ResourceAt`, piston availability/extended, and Live/Captured site tests are not constants. Initial selection is not a proof. |
| Exact guard interning | Compare leaf variant and every field; compare normalized ordered child IDs | Live and Captured tests never share a record; preserve resource/contact/site identities. No commutative sorting, SAT, distributivity, or state enumeration in production. |
| Literal-false branch removal | Defer | Callback links and routes must stay in correspondence. Erasing a delivery changes its sequence/provenance even if never dispatched; first slice changes only descriptions and references. |

For example, `All([Always, ResourceEnabled(r)])` becomes the original resource predicate. With r disabled both reject power; after re-enabling both allow it. Replacing the predicate with False from the initial state would fail the second observation. A Live Solid test may change after contact switching while a Captured Solid test remains true in the originating walk; their IDs must remain distinct.

There is a structural complication: `contact_guard_matches`, `guard_contains`, and `guard_contains_site_profile` validate receiver eligibility using guard identity/descendant syntax, not a general equivalence proof. For example, a delivery containing a contact selector `All([Always, g])` and that selector's remap must both refer to g after normalization. A reduction that erases a captured Profile predicate can fail receiver validation despite Boolean equivalence. Validate before and after; for the first slice reject such a transformation without publication rather than weakening Step 05 validation or adding a theorem prover.

## Minimal sequence and measurement gate

1. Finish review of Step 05 and identify the assembly owner of the electrical and callback plans. Keep structural/stage validity separate from execution admission.
2. Measure a baseline on identical small guarded-contact fixtures and at least one admitted schematic preparation: profiles/guards by kind, total child references, exact duplicate counts, links/sites/routes/deliveries, preparation wall time, and table allocation bytes (length and capacity plus boxed child arrays). Label these as accounted table bytes, not process peak memory.
3. Review and implement literal simplification only. Return a complete guard map and before/after counts, preserve all behavior records, and validate the transformed staged result before publication.
4. Add exact guard interning only if baseline duplication and paired measurements justify its own allocation/lookup cost. Add profile interning only if measured complete-record duplicates survive existing construction interning. Keep this in one small operation/module; no pass registry.
5. Review exact power dependency deduplication separately after assembly defines max-input semantics. Its key must contain full source, target, source/destination channel, guard, literal face, attenuation, and both conductor dust policies where applicable. Do not touch route deliveries, Update, Shape, stored/directional wire distinctions, or comparator override precedence.

No paired CPU/memory measurement was performed in B1, and no preparation or execution speedup is claimed. Consequently no extra pass, cache, hashing dependency, or profile rewrite is recommended unconditionally. Legacy `PassStatistics` already measures ordinary passes; it does not measure rich electrical/callback preparation. Use a temporary measurement harness or existing benchmark support before adding permanent telemetry. Do not benchmark the live Step 05 edits and report their timing as a reviewed stable baseline.

Runtime-sensitive reachability, electrical constant folding, coalescing, dust elimination, and piston/BUD/instant grouping wait for Steps 06-10 and differential replay. [Step 15](15-dust-optimization.md) additionally requires dust eligibility certificates, observer/shape/24-site liveness, stale-strength reconstruction, and paired active execution timings. A constant electrical value alone does not discharge these obligations.
