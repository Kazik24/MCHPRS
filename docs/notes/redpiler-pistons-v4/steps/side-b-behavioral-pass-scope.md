# Side B: scope of behavioral graph reduction

Status: proposed general scope, 2026-10-12. This defines the three requested passes; it does not implement them or claim an instant certificate for an existing fixture. [Basic-pass research](side-b-basic-passes-research.md) supplies the legacy reuse audit.

## Objective and placement

Reduce runtime nodes, callback deliveries, and event work in each optimized build by proving a smaller graph equivalent to the complete circuit. Construct the correct graph first. Analyze cable/power relations, ordered updates, state, and resource ownership together. Never infer a mechanism from its schematic name, actor count, or initial power/pose.

The pipeline is:

```text
inventory -> geometry -> electrical/query plans -> callback routes
    -> complete validated prepared circuit
    -> certify/specialize instant pistons
    -> eliminate ineffective update work
    -> reduce certified instant regions
    -> remove newly dead records and validate
    -> dense lowering -> graph execution
```

Use the existing optimization option for behavior reductions. Required graph construction and correctness remain independent of it. A failed or exhausted optimization proof retains the original graph region; it does not reject an otherwise admitted circuit. Parser admission errors remain errors. Cancellation preserves the original World and staged graph and prevents publication.

All three passes operate before `CircuitDraft::lower` creates dense incoming ranges. They consume the complete preparation, including electrical query plans still stored outside `CircuitDraft`. Do not convert to legacy Default/Side links or operate on an incomplete export. Start with three named semantic operations in a small module; no pass registry, plugin system, global truth-table extractor, solver dependency, or new user configuration.

## Reference semantics that constrain the design

The [piston model, sections 2-5](../../../PISTON_MODEL.md) and [piston.rs](../../../../crates/core/src/redstone/piston.rs) distinguish power availability, delivered sample, request, live acceptance, response, restoration, and rearm. Requests share an ordered queue and identical full request tuples are suppressed while pending. Acceptance can cancel a request after power or contact selection changes. Requests appended during the piston-action phase can execute in that phase; work generated by later restoration waits for the next applicable phase.

**Instant describes a causal response, not zero-time restoration of all piston state.** Retraction can immediately remove a far source's electrical contribution and trigger the next accepted operation before the action phase drains. Restoration still follows the reference lifecycle and can cause further observer/reset activity. A general noninstant piston can also remove a source immediately; source disappearance alone does not certify an instant mechanism or its reuse contract.

[piston/instant.rs](../../../../crates/core/src/redstone/piston/instant.rs) qualifies a narrow native retract/reset motif, including sticky state, redstone payload, downward observer/cap geometry, reset drive, companion records, and ownership exclusions. [InstantPistonCache](../../../../crates/core/src/world/instant_piston.rs) learns exact native stages and caches addresses. It retains native events, movement, callbacks, and live power queries. Its `proven` bit is not a graph-rewrite certificate and its candidate restrictions are not universal definitions of an instant circuit.

The [redstone model](../../../REDSTONE_MODEL.md) defines directional analog strength, max inputs, callbacks, scheduling, and ordered dust. A falling-event decoder can invert the apparent gate polarity: disappearance of both independent positive contributors corresponds to AND of their disappearance conditions; disappearance of a shared payload can correspond to OR of accepted owner actions. Inhibition must be effective before the relevant sample or acceptance. These are conditional projections, not permission to replace the full circuit with a settled Boolean truth table.

## Fit to the current Redpiler shape

The relevant current records are in [program_graph.rs](../../../../crates/core/src/redpiler/program_graph.rs), [electrical.rs](../../../../crates/core/src/redpiler/analysis/electrical.rs), and [callbacks.rs](../../../../crates/core/src/redpiler/analysis/callbacks.rs).

| Existing shape | What the passes use or preserve |
| --- | --- |
| `CircuitNodeKind`, node state, NodeId | Actor/component identity, saved wire strength and shape, specialized state ownership. Equal saved state does not permit merging actors. |
| `ElectricalLink`, `ElectricalTarget`, `ComparatorInputPlan` | Site-based source queries, literal face, attenuation, Main/Side/Quasi inputs, both conductor dust policies, stored wire strength, and live comparator overrides. |
| `Guard`, `StateTest`, `SiteTest`, `OperandView` | Local contact/state conditions and distinct live/captured queries. Analyze possible values, not only initial values. |
| `ContactSpec`, `ContactVariant`, `SiteSpec`, `Profile` | Which facts and callback receiver can be selected at each site. Site identity can remain necessary after its component is removed. |
| `PistonSpec`, `PistonRoutes`, `PistonState` | Lane/contact bindings, extended bit, availability, independent actor revision, change/restoration procedures. |
| `ResourceSpec`, `ResourceState` | One authoritative shared token, possible contacts, enable state, revision. Never split it into actor-owned copies. |
| `Route`, `RouteDelivery`, `CallbackEdgeRef` | Ordered synchronous deliveries, duplicate occurrences, direction, supplied view, receiver, and matching callback edge provenance. |
| `WirePlan`, `WireRelation` | Explicit traversal sites, ordered dust dependencies, ascent/descent, stored/directional channels, shape and captured Turbo procedures. |
| `CircuitDraft::lower` and validators | Checked IDs and ownership, guard acyclicity, incoming ranges, route sequence and edge correspondence after rewrites. Validation is not behavioral certification. |

Clock, queued requests, deferred connection events, general graph execution, and continuation reconstruction are specified by architecture and Steps 06-10; the current `CircuitState` does not yet implement that full shape. Reduced actor/region runtime representations are likewise proposed additions, not existing `NodeType` variants. A repeater node is a delayed component, not a substitute for a pure Boolean gate.

Keep analysis results temporary: incoming power/query users, callback callers, guard/site users, shared resource users, and scheduler/projection dependencies. Build indexes once using existing vectors/maps where useful. Record a certificate and original IDs for diagnostics; do not persist a generic analysis framework in runtime state.

The compiler techniques behind the three passes are established and can be applied locally:

| Pass | Model / technique | Application here |
| --- | --- | --- |
| Instant piston specialization | Partial evaluation under proved invariants; conservative abstract interpretation | Restrict the general piston transition rules to possible power/contact/update conditions and retain only behavior reachable under the certificate. |
| Update reduction | Effect analysis, liveness, and dead-code elimination | Remove a callback only when its state/scheduler/route effects cannot reach protected observations or distinguish continuation. |
| Instant region reduction | Circuit contraction and finite-state minimization | Replace a region with strength/logic relations or a smaller input/output transition machine; merge states only when all future boundary behavior agrees. |

These are proof methods, not a request to add general-purpose frameworks. An input/output transition machine can be a few named operations over existing graph state. Use explicit local rules for the first motifs and grow only when new evidence requires it.

## Common contract and proof scope

For a candidate region, name its boundary and establish a relation between original state and replacement state. For every permitted next input or dispatch operation, the related states must produce the same protected observations and reach related states with equivalent future work. A rewrite may omit internal no-effect operations only when supported inspection and continuation do not distinguish their omission. Preserve externally significant interleaving; an outside actor can run between FIFO requests even when both belong to the region.

The boundary includes:

- All incoming power channels and incoming callbacks, including duplicate, same-value, and captured deliveries; allowed host control actions and their operation boundaries.
- Outgoing directional/analog power and callbacks, observer-visible site changes, support/shape effects, commands, sound/block actions, and clock/phase-sensitive results.
- Every shared resource or externally read contact; pending request/tick/deferred ordering and membership that affect the environment.
- Projection/reset reconstruction and supported stepping boundaries. A removed visual block may retain immutable provenance; any state needed to reconstruct its exact current state and future must remain reconstructible.

Use structural transition rules and conservative local invariants first. Reachable-state reasoning starts from the imported state and covers arbitrary admitted input histories; if a reachable invariant cannot be proved, quantify over a conservative larger state set. Unknown power strength means 0..15 unless its emitter/channel gives a stronger proved bound. Unknown event order means all orders allowed by FIFO, phases, and nesting, not every arbitrary permutation.

Small finite enumeration is useful only if state, timers, event multiplicity, input domain, and transitions are complete and bounded. Unbounded feedback or accumulating work prevents that certificate; keep the original region. Differential tests support the rule implementation but do not prove all histories. No certification from two optimized models agreeing with each other.

Internal sample/request trace records should remain available to explain a reduction, mapping omitted operations to their proof reason. They need not force execution of an otherwise proven no-effect callback solely for logging. Required QC sampling and acceptance behavior at the region boundary cannot be omitted.

## Pass 1: certify and specialize instant pistons

**Input:** a general piston, its lane/resource alternatives, all normal/QC query sources, every possible base/head callback source, and their causal dependencies through cables and other components.

**Output:** the original actor or a certificate-backed specialized actor with a complete response/restoration/rearm contract. Record what is guaranteed (for example, same-action-phase propagation for a specified accepted action and boundary), which operations remain delayed, allowed blocked/drop/recapture cases, and the reachable state invariant. Do not use an unqualified `is_instant` bit to erase every timer.

Scope of analysis:

1. Resolve every guard-enabled source and receiver alternative, including prospective heads and disabled resources. Record which input changes can deliver a sample and which can change data without one.
2. Establish the action's causal path: trigger delivery, live sample, enqueue, acceptance, contact/output publication, nested routes, downstream requests, and later reset. Preserve the distinction between queued and accepted work.
3. Prove the same behavior for the complete permitted input domain, including an inhibit arriving before or after acceptance, held inputs, repeated updates, a change before a request is popped, and re-entry during restoration.
4. Include every outside writer of the affected resource and every outside reader of intermediate contacts. Prove exclusive ownership where relied upon; shared ownership requires a group certificate.
5. Determine the minimal retained logical state and pending work. Keep independent actor/resource revisions when obsolete-event cancellation remains possible. Reuse existing graph events and routes for restoration until those effects can themselves be reduced.

The first replacement should specialize existing semantic operations and dependencies, keeping PistonId/contact/resource bindings where possible. Its immediate saving is less general lane/guard/query work; no node-count reduction is promised merely by changing an actor's model. A proven reset circuit can later be absorbed into the actor as compact state/events, deleting observer/cable execution only after accounting for their complete effects. That absorption may span Passes 1 and 2.

**First slice:** one stationary sticky single-redstone-resource motif with exclusive resource use and completely inventoried reset paths. Use a known observer/reset example as a candidate, then include all external controls and its recurring held-input behavior. If the motif needs delayed restoration, retain it. Exclude shared transfer, transported components, analog reset thresholds, and externally observed intermediate sites from this initial specialization only when the certificate cannot handle them; those exclusions keep the original region rather than rejecting the build.

**Acceptance evidence:** one positive motif and a minimally changed negative motif with an alternate callback/power/reset writer; repeated cycles, held zero, early reversal, blocked operation, action cancellation, exact response order, and reset before restoration. A negative motif must be refused with its specific unproved dependency.

## Pass 2: eliminate ineffective update work

**Input:** ordered routes and callback edges, receiver transitions, channel/state invariants, and certificates from Pass 1.

**Output:** fewer deliveries and, when independently justified, fewer update-only producers, route records, and runtime nodes. Keep the relative order of surviving deliveries. Update/Shape families and supplied direction/view never merge merely because their target matches.

Use three increasingly strong rules:

| Rule | Required proof | Possible reduction |
| --- | --- | --- |
| Impossible delivery | Its guard is false in every reachable context, or it can resolve only to a receiver with no applicable operation. Include captured contexts and callback-family effects. | Remove that delivery and matching callback edge. |
| Identity transition | For every state/context where it runs, it changes no protected state, pending membership/deadline, host effect, nested route, shape, or future response. | Remove that occurrence. |
| Subsumed delivery | A retained occurrence gives equivalent behavior, and no intervening read/write, nested dispatch, pending-membership change, or capture makes the removed occurrence significant. | Remove a proved redundant occurrence; then analyze newly dead producers. |

Use the actual receiver rules to derive conditions. For example, a fixed component with no update handler may be an immediate no-op; an observer with a permanently nonqualifying supplied direction may be another, provided restoration/recovery rules cannot apply. Check [redstone dispatch](../../../../crates/core/src/redstone/mod.rs) and the specific handler before accepting either rule. A currently pending observer tick or a currently matched piston power/pose is only a state observation, not a universal condition.

Analyze effects by fields and semantic operations: sampled channels, component/resource state writes, scheduled work and membership, generated routes, host output, and reset state. Conservative summaries may prevent a reduction but must never hide an effect. Shape/support removal uses its own rules; do not run ordinary update no-op rules on Shape.

After deleting deliveries, compute liveness through power/query uses, guard/site dependencies, routes, wire traversal, observers, scheduler work, host output, resources, and projection. Remove a producer only if it has no retained effect or dependency. A wire with no remaining callback recipients can still carry power, retain a captured fact, or be needed for exact reset.

**First slice:** remove impossible or fixed-handler no-op deliveries. Then add one receiver-specific identity rule with a complete state-domain argument. Duplicate suppression and deletion of whole update circuits follow as separate small reviewed slices.

**Acceptance evidence:** QC data without delivery versus data with one essential delivery; unchanged comparator notifications; observer direction/pending behavior; repeated lamp deadlines; captured head eligibility; duplicate deliveries separated by a nested resource/contact change. Check route/edge correspondence and unchanged survivor order.

## Pass 3: replace instant regions with smaller logic graphs

**Input:** connected candidate regions of certified actors plus supporting cable/contact/update logic, with redundant work already reduced where useful. Candidate connectivity follows all semantic dependencies, not just power edges. A shared resource can make several actors one proof region.

**Output:** a smaller graph in one of these forms:

| Replacement | Eligibility | Retained obligations |
| --- | --- | --- |
| Stateless strength/logic relation | Response is a function of current inputs; no history, meaningful queued work, or externally significant internal ordering distinguishes states | Exact directional strength/attenuation, output callbacks and their causal timing, current-state reconstruction |
| Sampled state element | Data changes and sampling/update inputs are independent; state persists between valid accepted writes | Data/update separation, retained bit or contact choice, request/acceptance/cancellation, read/reset behavior |
| Compact instant transition graph | Several accepted actions, shared tokens, or reset/rearm histories affect future behavior | Minimum logical state, ordered boundary actions, necessary timers/revisions, resource conservation, exact continuation |

Derive relations from reference operations and declared signal decoders. Independent positive contributors disappearing together can become a falling-event AND relation; a shared source removed by any accepted owner can become an OR-like relation. Neither example establishes ordinary active-high AND/OR outputs or permits ignoring ownership/order. Inhibited response preserves when inhibition takes effect relative to sample and acceptance. BUD/storage regions require retained state; they cannot become a current-input combinational gate.

Use existing power links/guards/contacts for a reduced network whenever they express the resulting relation. Only add a narrowly defined pure relation or stateful kind when an actual reviewed replacement requires it. `Guard` currently has state/site predicates, not arbitrary signal expressions; `NodeType` currently has physical component behaviors, not general pure AND/OR nodes. Do not disguise a pure gate as a repeater or encode arbitrary execution in guard bytecode.

For sequential reductions, merge internal states only if every permitted next boundary operation produces equivalent observations and equivalent successor states. Preserve enough state to reconstruct removed components at every supported reset/inspection boundary. If exact reconstruction needs all former internal state, the candidate may save execution work but not much memory; measure that honestly.

Region contraction must preserve the outside scheduler's interleaving. If action A appends B behind an unrelated pending C, an atomic A+B evaluation would change acceptance order. Keep an event boundary or exclude the contraction. Internal callbacks may be fused only after proving intermediate effects unobservable and that nested work/order are preserved.

**First slice:** one small acyclic private-resource motif, no host command, no external observer of internal sites, no unaccounted analog consumer, and a proven response plus reset/rearm transition. Prefer a reduction into existing graph relations; if a new model is needed, implement just that demonstrated model. Expand to shared-resource joins, inhibition networks, and stateful memory motifs after individual boundary proofs.

**Acceptance evidence:** original graph/reduced graph/interpreter comparison for both input orders, inhibition before/after acceptance, repeated/overlapping triggers, held inputs, output strengths, pending reset, and continuation. Add an observer or analog consumer as a negative case. Check that a previously certified region remains certified or is retained when the new dependency invalidates the proof.

## Scope across callers, state, and exports

A behavioral rewrite reaches preparation assembly, lowering/validators, new specialized dispatch only where required, tests, inspection/provenance, and projection/continuation. Legacy ordinary passes and packed backend remain separate. No changes to fixture reference outputs, admission limits, or host configs to make a candidate pass.

When records are removed, return explicit old-to-new maps for changed tables and a removed-record disposition: replaced semantic owner, retained projection record, or certified no-effect record. Update every reference in nodes, links, sites, guards, contacts, resources, wire plans/relations, comparator plans, routes, and initial state/imported pending work. Compact IDs once near final lowering where practical.

Current route validation requires contiguous `sequence` values. After deleting a delivery, renumber surviving deliveries and rewrite their matching `CallbackEdgeRef.sequence` consistently. Keep original sequence/provenance in the rewrite report so inspection explains the deletion. Stable relative callback order is the runtime requirement; old numeric IDs belong in the map, not stale runtime references.

Check syntax-dependent guard receiver validation as described in B1. Never weaken it silently to accept a rewrite. Side A export must report the actual stage/capabilities and replacement/provenance records; lack of a viewer cannot block semantic checks. Removed components that remain needed for projection need descriptions, not executable simulation nodes or a native fallback.

## Delivery sequence and success criteria

1. Complete/review the executable model and continuation obligations in Steps 06-10. In parallel with that work, research one exact instant motif and its negative witnesses without rewriting the parser/runtime.
2. Implement Pass 1 recognition/certificate and one specialized model; preserve its delayed behavior initially.
3. Implement Pass 2's first route-removal rules, then one proved update-only region deletion.
4. Implement Pass 3's first region replacement, including projection and scheduler interaction.
5. Revisit update liveness only in affected regions, remove newly dead records, validate, lower, and measure. No global repeated reclassification unless a demonstrated dependency requires it.

For each slice, discover and execute its registered release/locked tests and relevant ordinary regressions. Require at least one successful reduction and one declined candidate; a pass that recognizes fixtures without reducing actual execution does not meet the goal.

Report paired original/reduced counts of executable nodes, power dependencies, route deliveries, queued/deferred operations, and retained reconstruction state. Measure preparation time/memory and active runtime on identical fresh fixture/input histories with repeated paired samples and correctness checks. Smaller export size or fewer nodes alone is not a speed claim. Build-time proof cost must be reported alongside runtime benefit.

The general all-circuit redundancy problem is outside scope. Each pass is conservative and useful on proved regions; unknown cases keep their complete graph. The initial objective is repeatable reduction of one real motif for each rule, followed by expansion using the same semantic boundaries.

## Review status

This scope uses source inspection and the known reference models. No Rust changes, executable tests, graph reductions, proof enumeration, or performance measurements were performed for this document. Its largest unresolved question is which first motif admits a compact replacement under arbitrary legal controls and exact continuation; resolve that with a certificate and counterexample before choosing runtime fields.
