# Plot-load failure and production spawn reset

The client progressed through login, but spawn's plot thread panicked on the unchecked result of loading `world/plots/p0,0`. Its header is save format 2. The `master` branch identifies that format as Minecraft 1.20.4, with a different chunk layout and two-sided signs. The recovered 1.18.2 piston branch's migration reader supports formats 0 and 1; format 2 remains explicitly unsupported rather than guessing its registry IDs or layout.

## Production recovery

With the user's authorization, accessed `urmom` over SSH and reset only spawn. The original file was moved to:

```text
/srv/mchprs/data/backups/plot-reset-2026-10-03/p0,0
```

SHA-256 before and after the move:

```text
6f8059161569e3152b1ac4ba3a9459fb9e1fa1f883db155a8a53cda899acfa29
```

Restarted `mchprs-mchprs-1`; the startup panic disappeared. An independent Minecraft 1.21.5 client (`SpawnProbe`) completed login and decoded a spawn chunk. Existing plots `p-1,0` and `p0,-1` were retained. They may still require a format-2 reader before they can be opened.

## Load-error handling

Local code now reports a failed load to the server instead of unwrapping it. The failed plot entry is removed, initial and queued players receive a disconnect reason, and their online entries are removed. Keeping the private-message receiver until the server drops its sender prevents queued players from being lost during cleanup. Shutdown also handles failed-load messages, avoiding a wait for a plot thread that never started. Template failures propagate through the same path. Incompatible chunk counts are rejected before constructing the plot world.

The new isolated `tools/run_plot_load_smoke.py` checks repeated entry into a rejected neighboring plot, unavailable spawn, an unreadable template, healthy-plot access, explicit client disconnect reasons and clean shutdown in three processes. Every rejected fixture remains unchanged. Production is still running the previously built image; the error-handling changes require a rebuild/deployment.
